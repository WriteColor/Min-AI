Se requiere una refactorización integral del asistente MIN AI, enfocada no únicamente en corregir errores funcionales, sino en rediseñar completamente su arquitectura interna, su sistema de razonamiento contextual, la administración de memoria persistente, la interacción con el sistema operativo y la coordinación entre módulos de automatización, visión, voz y ejecución de acciones.

Actualmente, aunque muchas funcionalidades aparentan existir a nivel estructural, en la práctica el comportamiento del asistente es inconsistente, poco determinista y con una capacidad extremadamente limitada para comprender contexto conversacional real. El sistema no mantiene continuidad entre interacciones, ignora memoria previamente almacenada, interpreta mensajes irrelevantes como instrucciones activas y ejecuta acciones arbitrarias debido a un pipeline deficiente de interpretación de intención, clasificación contextual y validación previa a la ejecución.

El sistema de memoria actual necesita ser reemplazado por un modelo de memoria híbrida persistente y contextual orientado a agentes LLM. La implementación debe contemplar memoria episódica, memoria semántica, almacenamiento de preferencias del usuario, tareas pendientes, objetivos, rutinas, sitios frecuentes, historial operacional y continuidad entre sesiones. La arquitectura debe permitir recuperación estructurada de contexto mediante embeddings, indexación semántica y mecanismos de inyección contextual dinámica, evitando que el modelo trate cualquier fragmento histórico como una instrucción inmediata. También debe existir soporte para actualización, eliminación, consolidación y priorización de memorias, incluyendo control de expiración y peso contextual según relevancia temporal y frecuencia de uso.

El asistente debe tener acceso operativo real al entorno del sistema. Actualmente muchas funciones aparentan existir únicamente a nivel superficial o mediante simulaciones incompletas. Se necesita una capa de integración nativa con Windows 11 que permita control confiable y verificable del sistema operativo utilizando APIs oficiales y mecanismos modernos de automatización. Esto incluye apertura y control de aplicaciones, interacción con ventanas existentes, detección de instancias activas, restauración de ventanas minimizadas, navegación dentro de interfaces gráficas, automatización de elementos UI, manipulación de archivos y directorios, acceso a terminales, control del escritorio, configuración del sistema, gestión de procesos, automatización del navegador y control multimedia.

El sistema debe diferenciar correctamente entre lanzar una nueva instancia de una aplicación y reutilizar una ventana ya existente. Actualmente el asistente tiende a reiniciar aplicaciones incluso cuando ya están abiertas, generando duplicación de procesos y pérdida de contexto operativo. Se requiere un sistema de administración de ventanas y procesos capaz de detectar estados activos, ventanas minimizadas, foco actual, jerarquía UI y contexto de ejecución antes de decidir una acción.

También debe implementarse un verdadero sistema de automatización UI multinivel. No basta con detectar ventanas; el asistente debe poder interactuar con componentes internos de aplicaciones mediante UI Automation, accesibilidad nativa de Windows, inspección de controles y mecanismos equivalentes a DOM para aplicaciones desktop. Esto debe permitir localizar botones, campos, listas, paneles y elementos interactivos incluso en aplicaciones desacopladas visualmente del shell de Windows. Las acciones ejecutadas deben ser verificables y auditables. El asistente no debe responder afirmando que completó una tarea si dicha tarea nunca ocurrió realmente. Toda acción crítica debe incluir validación posterior a la ejecución mediante observación del estado resultante.

El módulo de visión necesita separarse conceptualmente del módulo de control UI. La visión debe funcionar como una capa de observación contextual del sistema utilizando capturas de pantalla, análisis visual multimodal y monitoreo temporal configurable. Esta capa debe complementar el control de UI, no reemplazarlo. El asistente debe ser capaz de interpretar estados visuales reales, detectar cambios en pantalla, identificar errores visibles, monitorear interfaces y utilizar visión para confirmar resultados de acciones previamente ejecutadas.

El sistema de generación de imágenes requiere una reconstrucción completa. Actualmente existe un fallo evidente en la integración o selección de modelos que provoca respuestas repetitivas y plantillas visuales incorrectas independientemente de la instrucción del usuario. Debe implementarse un pipeline real de inferencia multimodal con selección dinámica de modelos compatibles según el proveedor activo y el tipo de generación solicitada. El sistema debe validar prompts, detectar fallos de inferencia y garantizar que las imágenes generadas correspondan realmente al contexto solicitado.

La lógica de ejecución de acciones presenta múltiples errores semánticos básicos. Existen casos donde el sistema interpreta operaciones matemáticas incorrectamente, utiliza símbolos erróneos o ignora instrucciones explícitas del usuario incluso después de múltiples correcciones. Esto evidencia deficiencias graves en el parser de intención, la representación interna de acciones y la validación de parámetros antes de ejecutar operaciones. Toda acción estructurada debe pasar por un pipeline determinista de interpretación, normalización y verificación.

El sistema de búsqueda web también necesita rediseño. Actualmente el asistente abre navegadores arbitrariamente cuando no comprende una tarea, aun cuando dicha acción no tiene relación lógica con la petición original. La navegación web debe ser considerada una herramienta contextual opcional y no una respuesta automática ante ambigüedad. Debe integrarse soporte real para motores de búsqueda mediante APIs externas, incluyendo capacidad de recuperar, resumir y utilizar resultados reales en lugar de únicamente abrir páginas sin procesar información. La integración con proveedores de búsqueda como Brave Search debe formar parte de una arquitectura modular desacoplada.

La gestión de archivos es extremadamente ineficiente. El asistente no debe depender de soluciones de emergencia mediante terminal para tareas básicas como crear archivos vacíos, renombrar documentos o modificar contenido existente. Debe existir una capa de filesystem abstraction robusta, con manejo correcto de permisos, validación de rutas, operaciones atómicas y feedback preciso sobre el resultado de cada acción.

El subsistema de audio y voz requiere una reconstrucción completa. El reconocimiento de voz es impreciso, mezcla idiomas incorrectamente y presenta errores frecuentes de transcripción. Debe implementarse un pipeline moderno de speech-to-text con detección de idioma, filtrado de ruido, supresión de eco y separación entre audio ambiente y comandos válidos. Actualmente el asistente interpreta música, voces del sistema o contenido multimedia como instrucciones activas, provocando ejecuciones aleatorias. Es indispensable integrar mecanismos de wake-word robustos, VAD avanzado, detección contextual de intención y cancelación acústica para evitar activaciones falsas.

La lógica contextual relacionada con multimedia también es deficiente. El sistema debe poder identificar correctamente estados reales de reproducción multimedia, incluyendo reproducción activa, pausa, buffering y cambios de dispositivo. Nunca debe pausar contenido que ya se encuentra reproduciéndose únicamente para “reanudarlo” después. Todas las acciones multimedia deben validarse mediante estado en tiempo real.

Las respuestas conversacionales del asistente son excesivamente genéricas y repetitivas debido a prompts estáticos y estructuras rígidas definidas en el núcleo del proyecto. Se necesita una reconstrucción del sistema de prompting dinámico para generar respuestas más naturales, variables y contextualmente adaptadas al historial del usuario, estado del sistema y situación actual. Los saludos, mensajes de finalización, confirmaciones y estados operativos deben generarse dinámicamente y no mediante plantillas predecibles.

El sistema también debe tener comprensión contextual real de fecha, hora y entorno. Actualmente utiliza saludos incorrectos según el momento del día y repite información climática innecesariamente. El módulo temporal debe utilizar horarios locales reales, estados contextuales y detección de cambios significativos antes de emitir información automática.

A nivel arquitectónico, se requiere soporte completo para múltiples proveedores de inteligencia artificial, tanto locales como remotos vía API. La implementación debe abstraer completamente la lógica de proveedores, permitiendo intercambiar modelos y backends en tiempo real sin reinicios, pérdida de estado ni interrupciones operativas. Cada proveedor debe utilizar correctamente su propia estructura API, formatos de mensajes, capacidades multimodales y mecanismos de autenticación.

Además del soporte multiproveedor, debe existir asignación especializada de modelos según el tipo de tarea. El sistema debe permitir configurar modelos específicos para razonamiento general, visión, voz, tiempo real, embeddings, automatización, generación de imágenes y procesamiento multimodal. La interfaz debe mostrar únicamente los modelos compatibles con el proveedor seleccionado actualmente, aplicando validaciones estrictas para evitar combinaciones inválidas.

El sistema de síntesis de voz también debe rediseñarse para funcionar correctamente con cualquier proveedor compatible. Debe existir una capa de abstracción universal para TTS y reproducción de audio, permitiendo incorporar nuevos proveedores futuros sin modificar el núcleo operativo del asistente.

Toda la estructura del proyecto necesita reorganización completa. Es necesario unificar directorios, modularizar responsabilidades, eliminar dependencias cruzadas innecesarias y redefinir la estructura de configuración. Deben eliminarse archivos obsoletos, código experimental, implementaciones de debugging y módulos de prueba que actualmente contaminan el proyecto principal. Los componentes críticos deben reconstruirse siguiendo principios de separación de responsabilidades, arquitectura desacoplada y extensibilidad modular.

La refactorización debe contemplar cambios profundos en rutas, nombres de archivos y organización interna. Todos los módulos existentes deben adaptarse a la nueva arquitectura, especialmente los componentes principales relacionados con inicialización, instalación, interfaz y núcleo operativo. El único componente que debe preservarse sin modificaciones estructurales importantes es el modelo local ubicado en @config\vosk_model.

Respecto a la interfaz gráfica, la implementación actual debe ser reemplazada completamente. La UI existente no es escalable ni adecuada para una arquitectura moderna basada en agentes multimodales. La transición debe orientarse hacia una interfaz web desacoplada del núcleo operativo, eliminando dependencias de puentes improvisados entre backend y frontend. La nueva UI debe diseñarse desde el inicio pensando en escalabilidad, observabilidad, monitoreo de agentes, configuraciones avanzadas, administración de proveedores, control de modelos y futuras expansiones funcionales.

Aunque inicialmente no es necesario implementar widgets avanzados, toda la arquitectura visual debe prepararse para soportarlos posteriormente de manera nativa. El panel de configuración debe exponer absolutamente todas las funcionalidades internas del sistema sin excepciones, incluyendo memoria, proveedores, modelos, automatizaciones, audio, visión, accesibilidad, integraciones, comportamiento contextual, seguridad y control operativo del asistente.
